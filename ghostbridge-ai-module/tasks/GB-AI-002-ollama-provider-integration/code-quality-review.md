### Judgement on the flagged deviations and public types
- **D1 (provider implements `AiProvider`, not `AiClient`):** correct and preferable. Implementing `AiClient` would bypass the coordinator's validation, limiter, budget, retry, telemetry and structured validation. The chain `DefaultAiCoordinator(AiClient) → AiProvider → OllamaAiProvider` matches the existing SPI.
- **D2 (`…VO` suffix only on package-private wire records in `service.impl`):** reasonable. The records are encapsulated next to the adapter, the public `AiRequest`/`AiResponse` are not renamed, and the names are unique repo-wide. The repo does not otherwise use a "VO" convention, which is acceptable for adapter-internal types.
- **`OllamaAiProvider` and `AiProperties.Ollama` being public:** acceptable. `AiAutoConfiguration` (package `config`) has to construct the provider and reference its type for `@ConditionalOnMissingBean` and the `LazyInitializationExcludeFilter`, following the precedent of `MockAiProvider`. Its public surface is the `AiProvider` SPI plus a constructor taking validated configuration. No `HttpClient`, `HttpRequest` or wire VO appears in a public signature. `AiProperties.Ollama` must be public as part of the `@ConfigurationProperties` record. Its canonical constructor re-validates the destination, and `withApiKey` returns a re-validated copy, not a mutation. The caveats are CQ-12 (the test seam) and CQ-16 (byte limits not validated outside Spring binding).

## Things verified OK
- **Boundaries:** ai-core has no dependency on web or app and no new dependency or module, and no POM changed. The provider types are confined to `service.impl`. Literals are accessed as `GhostBridgeAiLiterals.X` with a normal import. The only static imports anywhere in the module are AssertJ (tests), and there are no wildcard imports.
- **Naming:** no duplicate simple class names repo-wide. All new classes carry the `Ai` or `Ollama` domain token. There is one public top-level type per file; the VOs, the subscriber and the stub are package-private.
- **Java 21 idioms:** records for configuration and VOs, pattern-matching `instanceof` in `AiSecret.equals`, and constructor injection only. There is no field injection and no `System.out` in main code.
- **Exception handling:** no catch of `Exception` or `Throwable` in main code. Each catch maps to a typed `AiException` with a generic message. Interrupt handling restores the flag and cancels the future (CQ-03 is a coverage gap, not a code defect). Error-status bodies are discarded unread through `BodySubscribers.replacing`.
- **Thread safety:** the provider is stateless apart from a thread-safe `HttpClient` and `ObjectMapper`. One subscriber is created per response, and Flow signals are serial, so the subscriber needs no synchronisation. Backpressure through `request(1)` per `onNext` is correct. `reject()` cancels the subscription and completes the future exceptionally. A declared `Content-Length` above the limit is rejected in `onSubscribe` before any `request`. The overall deadline is enforced with `future.get(timeout)`, and the timeout path calls `future.cancel(true)`, which aborts the exchange on modern JDKs. There is no assertion that the connection actually closes.
- **Request size:** the request is serialised to `byte[]` and checked against `maxRequestBytes` before any I/O, which tests confirm (the stub receives 0 requests).
- **`AiSecret`:** it is a final class rather than a record, so there is no auto-generated `toString`. `toString`/`@JsonValue` return the mask. `equals` compares in constant time, and `hashCode` is constant and does not depend on the value. `reveal()` is called in one place only (`OllamaAiProvider.buildRequest`).
- **Complexity:** every method is estimated at 10 or less.
- **Live test:** it is tagged `live-provider` and needs `-Dlive.provider=true` plus both environment variables. It was skipped in this build and made no network call.
- **`.env.example`:** it holds only empty placeholders (`OLLAMA_API_KEY=`, `GHOSTBRIDGE_AI_PROVIDER=`, `GHOSTBRIDGE_AI_MODEL_ID=`).
