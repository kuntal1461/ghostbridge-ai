# Kiroween 2026 Hackathon Requirements

## Project

- **Full name:** GhostBridge AI
- **Tagline:** Resurrect Legacy Systems. Bridge the Future.
- **Submission title:** GhostBridge AI - Transform Legacy SOAP APIs into Modern REST Services Using AI
- **Category:** Resurrection
- **Core goal:** Reimagine obsolete SOAP technology with AI and present it as a modern REST-based service.
- **Intended stacks:** Spring Boot backend and React + TypeScript frontend.

| Milestone | Deadline |
| --- | --- |

Late submissions are not accepted.

## Eligibility and Project Rules

- Entrants must be eligible individuals, teams, or organizations under the official rules.
- Teams can contain a maximum of three participants.
- The project must be newly created during the Submission Period.
- The project must use Kiro: IDE, CLI, Web, Crew, or a combination.
- Insufficient use of Kiro can result in disqualification.
- Standard frameworks and libraries may be used, but pre-existing code or work must be disclosed.
- Third-party SDKs, APIs, and data may only be used under their terms and licenses.
- The submitted project must be original and must not violate another person's or organization's intellectual property rights.
- The project must work consistently on the platform for which it is submitted.
- Judges may evaluate the working app, text description, images, and demonstration video.

## Required Submission Materials

1. **Public GitHub repository**
   - Public URL.
   - GitHub, not GitLab or BitBucket.
   - All source code, assets, dependencies or dependency setup, and instructions.
   - A repository-visible open-source license file, such as MIT or Apache 2.0.
   - A root `/.kiro` directory containing evidence of specs, hooks, steering, and related Kiro usage.
   - Do not add `/.kiro` or its subdirectories to `.gitignore`.

2. **Working application**
   - Public app URL or a functioning demo/test build.
   - Login credentials and testing instructions inside the Devpost submission if authentication is required.
   - The app must remain available free of charge during the judging period.

3. **Text description**
   - Explain the problem, intended audience, features, end-to-end functionality, and differentiators.
   - Identify the Resurrection category and any applicable bonus categories.

4. **Demonstration video**
   - Less than three minutes.
   - Public and visible on YouTube.
   - Shows the app working on the platform built for.
   - Use only appropriately licensed or original music and material.
   - The demo should show the complete user journey rather than only code.

5. **Kiro usage write-up**
   - Explain how Kiro was used and why the approach was effective.
   - Cover the relevant features used, for example:
     - Kiro IDE, CLI, Web, or Crew
     - Custom agents
     - Agent hooks
     - Spec-driven development
     - Steering documents
     - MCP integrations
     - Property-based testing
     - Kiro powers
   - Explain the comparison or value versus a purely vibe-coded workflow where relevant.

## Optional Bonus Eligibility

Submit only the bonuses for which the entry is genuinely eligible.

- **Best Student Project:** Confirm student status and provide the requested academic information for every team member.
- **Best Startup Project:** Confirm founder status and provide LinkedIn and startup website details.
- **Best Ghost of Kiroween Past:** Confirm participation in Kiroween 2025.
- **Best Kiro Crew App:** Provide a separate public GitHub repository for the Kiro Crew app and a feature/functionality write-up.
- **Social Blitz:** Post during the submission period. The post must start with `#KiroweenHackathon26` and explain a favorite Kiro feature and how it changed development.
- **Bonus Blog:** Publish a public third-party blog post during the submission period, mention that it is part of Kiroween Hackathon 2026, and provide the URL.

## Judging Criteria

Each criterion is weighted equally at 20%:

| Criterion | What judges evaluate |
| --- | --- |
| Potential Impact | Real problem, real audience, credible usefulness, and accessibility |
| Technological Implementation | Depth and effectiveness of Kiro use, AI-development strategy, and experimentation |
| Design | Complete, coherent, polished, and intentional product experience |
| Innovation/Idea | Creativity, novelty, and unusual or effective technology combinations |
| Presentation | Clear end-to-end video, understandable pitch, and memorable presentation |
